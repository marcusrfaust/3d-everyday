3d-Everyday (3DE) — implementation-notes

Resumo

Vitrine nova (3de.focol.ai) sobre o catálogo do 3d-lib (somente leitura). Base estrutural: withastro/storefront (referência isolada em /tmp/storefront-ref, nunca commitada). Fase 1: casco + leitura readonly. Fase 2: créditos. Fase 3: Medusa.

Decisões de Arquitetura

  • 3d-lib intocado: watcher + PG + D1 continuam; 3DE lê o D1 via REST server-only (mesmo padrão web/src/lib/d1.ts).
  • Astro 5 SSR + Tailwind v4, sem React na fase 1; islands só se justificadas.
  • Sem Stripe/Loops/Maps do storefront; checkout de reserva herdado do 3d-lib quando chegar a hora.
  • Taxonomia Jev (23 mapeamentos tag→categoria) vira navegação por facetas (categoria/tag/formato).
  • Medusa só na fase 3, plugado no 3DE — nunca no 3d-lib.
  • Pendências de produto (planos/créditos): quantos planos, expira ou acumula, re-download gasta de novo — aguardando Marcus.

Arquivos Criados/Alterados

  • PRODUCT.md — contexto durável (impeccable init, fatos inferidos marcados).
  • package.json / astro.config.mjs / tsconfig.json / .env.example / .gitignore — scaffold Astro 5 SSR.
  • src/lib/d1.ts — cliente D1 readonly (sem d1exec).
  • src/lib/catalog.ts — listItems/countItems/categories readonly.
  • src/layouts/Layout.astro — casco (nav + footer + slot).
  • src/pages/index.astro — home: grade de peças recentes com foto via thumb-proxy.
  • src/pages/api/thumb/[fileId].ts — proxy de foto (D1 local_path/Drive) — a implementar fase 1b.
